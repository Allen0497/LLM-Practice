## 第二章：训练阶段的"为什么"——每一步在解决什么问题

每个训练阶段都不是凭空冒出来的，而是上一步遗留问题的解药。理解"为什么"比记住"是什么"重要 100 倍。

### 2.1 预训练：让模型学会"语言"

**问题：** 一个随机初始化的 Transformer 不会任何东西。

**解药：** 喂海量文本，让它学习"给定前面，预测下一个 token"。

```
Loss = -log P(x_t | x_1, x_2, ..., x_{t-1})
       ↑
     给模型看前 t-1 个 token，让它预测第 t 个

副产品：
  ✓ 词汇理解
  ✓ 语法
  ✓ 世界知识（"巴黎是法国首都"）
  ✓ 简单推理（"苹果是水果"）
```

**遗留问题：** 模型只会"续写"，不会"对话"。问它"今天天气？"它可能回"今天天气很好，明天天气更好，后天天气..."—— 因为它见过的是文章，不是对话。

### 2.2 SFT：让模型学会"听话"

**问题：** 预训练模型是"百科全书"但不是"助手"。

**解药：** 用 (指令, 回答) 数据对继续训练，模型学会"看到用户提问就给出回答"的格式。

```
训练数据格式（ChatML）：
  <|im_start|>user
  介绍一下 Python<|im_end|>
  <|im_start|>assistant
  Python 是一种...<|im_end|>

关键：只对 assistant 部分算 loss（DataCollatorForCompletionOnlyLM）
理由：让模型学"怎么回答"，而不是学"怎么提问"
```

**遗留问题：** SFT 教会了模型"什么是好回答的格式"，但没教"什么是好回答的内容"。SFT 数据里如果有不安全/不真实的回答，模型也会模仿。

### 2.3 偏好对齐：让模型分清"好坏"

**问题：** SFT 后的模型可以好好说话，但不知道哪种说法更好。

**解药：** 提供成对数据 (chosen, rejected)，告诉模型"在两个备选中，人类更喜欢哪个"。

#### 路线 A：DPO（直接偏好优化）

```
核心思想：跳过 RM，直接用偏好数据优化模型

Loss = -log σ(β · (log π_θ(chosen) - log π_θ(rejected)
              - log π_ref(chosen) + log π_ref(rejected)))

含义："让 chosen 的概率 / rejected 的概率 比 ref 模型更大"

优点：简单、稳定、不用训 RM
缺点：完全依赖偏好数据质量
```

#### 路线 B：RM + PPO（经典 RLHF）

```
两阶段：
  Step 1（RM）：训一个评分模型
    Loss = -log σ(score_chosen - score_rejected)
    输出：给任意 (prompt, response) 打分

  Step 2（PPO）：用 RM 做 RL
    Reward = RM(generated_response) - β·KL(π_θ ‖ π_ref)
    PPO 目标：max E[reward]，但不偏离 ref 太远（KL 约束）

优点：奖励信号是连续的，可以从 RM 蒸馏到任意采样
缺点：复杂，4 个模型同时跑（actor/critic/ref/RM）
```

#### 路线 C：GRPO（DeepSeek-R1 推理路线）

```
核心创新：
  1. 不用 RM，直接用规则奖励（数学题对错、格式合规）
  2. 不用 critic，组内归一化代替

流程：
  - 同一个 prompt 采样 G 个回答
  - 对 G 个回答打分（基于规则或 RM）
  - 组内归一化：A_i = (r_i - mean) / std
  - 用 PPO-like 损失更新

优点：极致简洁，对推理任务效果好
关键应用：DeepSeek-R1 的"自主长思维链"就是 GRPO 训出来的
```

### 2.4 三条路线的对比

```
┌──────────────┬─────────────┬───────────────┬─────────────────┐
│              │   DPO       │  RM + PPO     │   GRPO          │
├──────────────┼─────────────┼───────────────┼─────────────────┤
│ 复杂度       │ ⭐          │ ⭐⭐⭐⭐       │ ⭐⭐            │
│ 显存         │ 1 模型      │ 4 模型        │ 1 模型 + 采样    │
│ 数据         │ 偏好对      │ 偏好对        │ 规则可判（数学等）│
│ 适合任务     │ 通用对齐    │ 通用对齐+精调  │ 推理（RL Reasoning）│
│ 训练稳定性   │ 高          │ 中（要调参）  │ 高              │
│ 代表项目     │ Zephyr      │ ChatGPT       │ DeepSeek-R1     │
└──────────────┴─────────────┴───────────────┴─────────────────┘
```

### 2.5 蒸馏：让小模型继承大模型能力

**问题：** 训出来的大模型推理慢、贵。生产环境想用小模型。

**解药：**
- **数据蒸馏**：大模型批量生成数据 → 喂给小模型 SFT
- **模型蒸馏**：让小模型的 logits 分布对齐大模型

```
数据蒸馏（最常用，也是 mini_qwen 用的）：
  Step 1: 用 DeepSeek-R1（老师）生成 (问题, 推理过程, 答案)
  Step 2: 用这些数据 SFT Qwen-0.5B（学生）
  → 小模型也学会了"先思考再回答"

模型蒸馏（对齐分布）：
  Loss = α · CE_loss(student, label)
       + (1-α) · KL_loss(student_logits, teacher_logits / T)
  T 是温度系数，softmax 输出分布更"软"
```

## 第三章：技术选型脉络（5 条主线）

整个 mini_qwen 项目里，每一项技术都不是孤立的。把它们按"主线"梳理，能更清楚地看见连接。

### 主线 1：训练框架的演进

```
训练范式：
  PyTorch DDP（数据并行，每卡完整模型）
        ↓
  DeepSpeed ZeRO Stage 1（拆 Adam 状态）
        ↓
  DeepSpeed ZeRO Stage 2（+ 拆梯度）
        ↓
  DeepSpeed ZeRO Stage 3 / FSDP（+ 拆参数）
        ↓
  + CPU offload（极致省显存）

mini_qwen 选择：accelerate + DeepSpeed ZeRO Stage 1
理由：0.5B 模型 + 3 卡训练，不需要更激进的分片
```

### 主线 2：参数高效微调（PEFT）演进

```
全参数微调：所有参数都更新
  ↓ 太贵
LoRA（低秩适配）：只训 A、B 矩阵
  ↓ 还可以更省
QLoRA（4-bit 基座 + LoRA）
  ↓ 多任务切换
LoRA Hub（一基座 + 多 adapter 动态加载）

mini_qwen 选择：
  - 预训练：全参数（基座必须从零学）
  - SFT：可选 LoRA
  - RM：LoRA（防止灾难性遗忘）
  - DPO/PPO/GRPO：可选 LoRA
```

### 主线 3：偏好对齐方法的演进

```
2017  PPO（OpenAI 提出 RL 算法）
2022  RLHF（InstructGPT 论文）
        - 三步：SFT → RM → PPO
2023  DPO（Stanford 提出）
        - 跳过 RM，直接优化
2024  其它 DPO 变体：IPO, KTO, SimPO, ORPO
2024  GRPO（DeepSeekMath）
        - 推理任务专用
2025  DAPO, REINFORCE++ (改进版本)

mini_qwen 学习路径：
  RM + PPO（理解原版 RLHF）
  DPO（更简洁）
  GRPO（前沿）
```

### 主线 4：推理加速的演进

```
HuggingFace transformers 原生 generate
   ↓ 8x 加速
HuggingFace transformers + Flash Attention 2
   ↓ 24x 加速（批量场景）
vLLM（PagedAttention + Continuous Batching）
   ↓ 接近极致
TensorRT-LLM（NVIDIA 卡）
SGLang（KV cache 复用最强）

部署链路：
  训练完 LoRA → merge_peft_adapter.py 合并 → vLLM serve
```

### 主线 5：应用层的演进

```
裸模型对话（qwen_chat.py）
   ↓ 加思维链
R1 风格对话（qwen_r1_chat.py）
   ↓ 加外部知识
```

## 第四章：核心公式与速记

### 4.1 预训练 / SFT 损失

```
Cross-Entropy Loss（贯穿整个项目）：
  L = -Σ log P(x_t | x_1, ..., x_{t-1})

SFT 的关键变体：
  - 只对 assistant 部分计算（label 上 mask 掉 user 部分为 -100）
  - DataCollatorForCompletionOnlyLM 自动处理
```

### 4.2 DPO 损失

```
L_DPO = -log σ(β · [log(π_θ(y_w|x)/π_ref(y_w|x))
                  - log(π_θ(y_l|x)/π_ref(y_l|x))])

含义：让 chosen 相对于 ref 的"提升"，大于 rejected 的"提升"
β：温度系数，通常 0.1-0.5
```

### 4.3 RM 损失

```
L_RM = -log σ(r_θ(x, y_w) - r_θ(x, y_l))

含义：让 chosen 的分数比 rejected 高
注意：用最后一个 token 的隐状态过 reward head 得到 r
```

### 4.4 PPO 目标

```
L_PPO = E_t [min(ratio_t · A_t, clip(ratio_t, 1-ε, 1+ε) · A_t)]
        - β · KL(π_θ ‖ π_ref)

ratio_t = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)
A_t：优势函数（Advantage），衡量动作好坏
ε：clip 范围，通常 0.2
β：KL 惩罚系数
```

### 4.5 GRPO 目标

```
对每个 prompt 采样 G 个回答 {y_1, ..., y_G}：
  打分：r_i = R(y_i)  （规则或 RM）
  归一化：A_i = (r_i - mean(r)) / std(r)
  
L_GRPO 类似 PPO，但用 A_i 替代 GAE 优势

精髓：用组内统计量代替 critic
```

### 4.6 LoRA 公式

```
原始：y = Wx
LoRA：y = Wx + (α/r) · B(Ax)

参数量：r × (d_in + d_out)
合并：W_merged = W + (α/r) · BA
```

### 4.7 显存估算

```
全参数训练（fp16 + Adam fp32）：
  显存 ≈ 参数量 × 16 bytes + 激活

  其中 16 bytes/param = 2(参数) + 2(梯度) + 8(Adam m+v) + 4(主权重)

LoRA 训练（基座冻结）：
  显存 ≈ 基座 × 2 + LoRA 参数 × 16 + 激活
        ≈ 基座 × 2 + 激活
```

### 4.8 注意力机制

```
Self-Attention：
  Attention(Q, K, V) = softmax(QK^T / √d_k) V

GQA（Grouped Query Attention，Qwen 使用）：
  多个 Q head 共享一组 K/V head
  → 显著降低 KV cache 大小，推理更快

RoPE 位置编码：
  q_m = R_m · q   （旋转矩阵 R_m 跟位置 m 有关）
  k_n = R_n · k
  q_m · k_n = q · R_{n-m} · k  ← 只与相对位置有关
```

## 第七章：工程实践经验汇总

### 7.1 训练前必做的 Checklist

```
✅ 模型路径：用绝对路径（避免不同进程 cwd 不一致）
✅ 数据预处理：tokenized 数据落盘（重启不重新处理）
✅ wandb：设好 project/run name，方便对比
✅ 日志：nohup ... > logs/xxx.log 2>&1 &
✅ checkpoint：save_total_limit=3（防磁盘爆）
✅ eval：先 num_examples=10 跑通流程
✅ 显存：先用单步 batch=1 验证不 OOM
✅ 环境：固定 transformers / trl / peft 版本
```

### 7.2 调试技巧

```python
# 技巧 1：IPython.embed 暂停（qwen_mem.py 用了）
import IPython; IPython.embed()
# 进入交互 shell，手动检查 model、显存、变量

# 技巧 2：先小数据快跑通
TRAIN_SUBSET = 100   # 调试时用，正式跑设 -1

# 技巧 3：显存监控
class CUDAMemoryCallback(TrainerCallback):
    def on_step_end(self, args, state, control, **kwargs):
        if state.global_step % 100 == 0:
            print(f"Step {state.global_step}: "
                  f"{torch.cuda.memory_allocated()/1024**3:.2f} GB")
trainer.add_callback(CUDAMemoryCallback())

# 技巧 4：trainer.train(resume_from_checkpoint=True)
# 训练中断后恢复，不用从头跑

# 技巧 5：梯度异常检测
torch.autograd.set_detect_anomaly(True)   # 反向时检测 NaN/Inf 来源
```

### 7.3 选择技术栈的决策树

```
要训练大模型 →
    显存够 → DDP（accelerate launch）
    显存不够 →
        多卡 → DeepSpeed ZeRO-1 → -2 → -3 → CPU offload
        单卡 → LoRA → QLoRA

要做偏好对齐 →
    简单 / 数据有限 → DPO
    要精细控制 / 偏好复杂 → RM + PPO
    推理任务（数学/代码）→ GRPO

要做 RAG →
    简单单跳问答 → 传统 RAG
    多跳推理 / 需要工具组合 → Agentic RAG

要部署 →
    单机服务 → vLLM
    高 QPS / 多模型 → SGLang + 路由层
    边缘设备 → llama.cpp + GGUF
```

### 7.4 学习时容易踩的坑

```
坑 1：训练时和推理时 prompt 格式不一致
  现象：模型推理时输出乱七八糟
  解决：训练用什么模板，推理就用什么模板（ChatML 严格一致）

坑 2：评估时 temperature 不为 0
  现象：每次跑分数都不一样
  解决：评估时永远 temperature=0，可复现

坑 3：偏好对齐时学习率太大
  现象：模型崩坏（输出乱码）
  解决：DPO/PPO 的 lr 通常 1e-7 ~ 5e-6（远小于 SFT）

坑 4：DataCollator 未配置 / 配错
  现象：模型学习了 user 提问的内容（在抄题目）
  解决：必须用 DataCollatorForCompletionOnlyLM

坑 5：LoRA 合并前忘记 model.eval()
  现象：合并后模型行为奇怪
  解决：merge_and_unload() 前必须 eval()

坑 6：训练 R1 模型推理时不加 system prompt
  现象：模型不思考、直接输出答案
  解决：训练用什么 system prompt，推理时严格一致

坑 7：vLLM 加载未合并的 LoRA checkpoint
  现象：vLLM 认不出 adapter 文件
  解决：先 merge_peft_adapter，再用 vLLM 加载完整模型
```

### 7.5 性能优化的优先级

按"性价比"（提升/代价）排序：

```
1. bf16=True               ★★★★★（0 代价，立刻省 25%+）
2. flash_attention_2       ★★★★★（0 代价，速度 2-3x）
3. gradient_accumulation   ★★★★（无显存代价，效果等效大 batch）
4. tokenize 数据缓存       ★★★★（重启训练免重复处理）
5. gradient_checkpointing  ★★★（速度 -25% 但激活 -75%）
6. LoRA                   ★★★（代价：效果略降）
7. vLLM 替代 HF 推理       ★★★★★（部署时 5-24x 加速）
8. DeepSpeed ZeRO-1        ★★★★（多卡训练降显存）
9. ZeRO-3 + offload        ★★（最后的手段，慢）
10. QLoRA / 量化           ★★（精度有少许损失）
```

## 🎉 结语

走到这里你完整通关了 mini_qwen 项目。回头看，从你最初打开第 1 篇笔记开始：

```
那时你以为要学的是：怎么训练大模型？
现在你知道，真正学到的是：
    - 怎么从无到有把语言能力压进权重（PT）
    - 怎么让模型学会做事（SFT）
    - 怎么让模型分辨好坏（DPO/RM/PPO/GRPO）
    - 怎么让模型推理得更深（GRPO + 蒸馏）
    - 怎么让模型评估其他模型（LLM-as-Judge）
    - 怎么让模型自主决策（Agent + RAG）
    - 怎么让训练真的跑得起来（显存优化）
```

更重要的是，你掌握的不是任何具体的"框架"或"算法"，而是一套思考大模型的方法：

```
对每一个新技术，你会问：
  - 它在解决上一步遗留的什么问题？
  - 它的代价是什么？
  - 我应该把它放在流程的哪一步？
  - 它和我已经会的东西怎么连？
```

这套思维方式，会让你在大模型领域走很远。

> 任何新东西都能被你"插"进合适的位置，迅速理解。
