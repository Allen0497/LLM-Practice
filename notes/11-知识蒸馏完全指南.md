## 第一章：什么是知识蒸馏？

### 1.1 为什么需要蒸馏？

```
现实问题：
  大模型（如 DeepSeek-R1 671B）推理能力很强
  但部署成本极高：需要多张 A100/H100，推理速度慢，费用高

  小模型（如 Qwen2.5-0.5B）部署成本低
  但推理能力弱：直接训练很难达到大模型的水平

知识蒸馏的目标：
  ┌─────────────────────────────────────────────┐
  │  大模型的能力  ──→  迁移到  ──→  小模型     │
  │  (Teacher)                      (Student)    │
  │                                              │
  │  671B 参数的推理能力                         │
  │       ↓ 蒸馏                                 │
  │  0.5B~7B 参数也能推理                        │
  └─────────────────────────────────────────────┘

效果（DeepSeek-R1 论文数据）：
  DeepSeek-R1-Distill-Qwen-7B 在数学推理上
  超过了很多未蒸馏的 70B 模型！
  → 蒸馏可以让小模型"以小博大"
```

### 1.2 蒸馏的核心思想（Hinton 2015）

```
Geoffrey Hinton 在 2015 年提出知识蒸馏的核心洞察：

  大模型的 softmax 输出包含"暗知识"（Dark Knowledge）

  例如：对于输入"猫坐在___上"，预测下一个词：
    大模型输出概率：
      "垫子" → 0.60
      "沙发" → 0.25
      "椅子" → 0.10
      "桌子" → 0.03
      "天花板" → 0.001
      ...

  如果只看最终答案"垫子"，我们丢失了很多信息。
  但概率分布告诉我们：
    - "沙发"和"椅子"也是合理的（概率不低）
    - "天花板"是不合理的（概率极低）
    - "沙发"比"椅子"更可能（0.25 > 0.10）

  这些"相对关系"就是暗知识！
  Student 通过学习这个分布，能学到比单纯标签更多的信息。
```

### 1.3 温度（Temperature）的作用

```
温度 T 用于软化概率分布：

  softmax(z/T) 中：
    T=1：原始分布（尖锐）
    T>1：分布变平滑（暗知识被放大）
    T<1：分布变��锐（接近 one-hot）

  例如 logits = [3.0, 1.5, 0.5]：

  T=1（原始）：[0.78, 0.17, 0.05]  → 几乎只看到第一个
  T=2（软化）：[0.55, 0.27, 0.18]  → 能看到三者的关系
  T=5（很软）：[0.40, 0.33, 0.27]  → 三者差距很小

  温度越高，小概率选项的信息越明显
  → Teacher 的"思考过程"被更充分地传递给 Student
```

## 第二章：两种蒸馏路线 —— 数据蒸馏 vs 模型蒸馏

### 2.1 路线对比

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                   │
│  路线 A：数据蒸馏（qwen_distill_data.py）                        │
│  ═══════════════════════════════════════                          │
│                                                                   │
│  Teacher 模型 ──→ 生成带推理链的回答 ──→ 蒸馏数据集              │
│                                              ↓                    │
│                                    Student 做 SFT 学习            │
│                                                                   │
│  本质：Student 模仿 Teacher 的"输出文本"                         │
│  类比：学生抄老师的解题过程                                       │
│                                                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  路线 B：模型蒸馏（qwen_distill.py）                             │
│  ═══════════════════════════════════                              │
│                                                                   │
│  Teacher 和 Student 同时前向传播                                  │
│       ↓                                                           │
│  对齐 logits 概率分布（KL 散度）                                 │
│       ↓                                                           │
│  Student 学习 Teacher 的"思维方式"                               │
│                                                                   │
│  本质：Student 对齐 Teacher 的"概率分布"                         │
│  类比：学生学习老师的思考方式，而非只抄答案                       │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 两种路线的优劣

| 维度 | 数据蒸馏 | 模型蒸馏 |
|------|---------|---------|
| **实现复杂度** | 低（生成数据 + SFT） | 中（需要自定义 Trainer） |
| **显存需求** | 低（分两步，不同时加载） | 高（同时加载 Teacher + Student） |
| **信息传递** | 只有最终文本 | 完整的概率分布（暗知识） |
| **Teacher 要求** | 只需要能推理 | 需要与 Student 架构兼容 |
| **效果上限** | 较低 | 较高 |
| **适用场景** | Teacher 很大无法同时加载 | Teacher 和 Student 可以同时加载 |
| **DeepSeek 用法** | R1 → 生成数据 → SFT 小模型 | 同时训练，对齐分布 |

### 2.3 实际中的组合使用

```
DeepSeek-R1 的完整蒸馏流程（两种路线结合）：

步骤 1：数据蒸馏（生成训练数据）
  DeepSeek-R1 (671B) 对 80 万道数学题生成带推理链的回答
  → 得到高质量的 (problem, reasoning_chain) 数据集

步骤 2：SFT 冷启动
  用步骤 1 的数据对小模型做 SFT
  → 小模型初步学会推理格式

步骤 3：模型蒸馏（可选，进一步提升）
  用 Teacher 的 logits 分布指导 Student 训练
  → 小模型学到更细粒度的"思维方式"

本项目的实现：
  qwen_distill_data.py → 步骤 1（数据蒸馏）
  qwen_distill.py      → 步骤 2+3（SFT + KL 蒸馏的联合训练）
```

## 第三章：数据蒸馏详解（qwen_distill_data.py）

### 3.1 distilabel 框架

```
distilabel 是 Argilla 开发的 LLM 数据生成框架：

核心概念：
  Pipeline：数据处理流水线（DAG 有向无环图）
  Step：流水线中的每个处理步骤
  LLM：大语言模型后端（支持 vLLM、OpenAI、HuggingFace 等）

为什么用 distilabel 而不是直接写推理代码？
  1. 自动处理批量推理、错误重试、进度保存
  2. 支持多种 LLM 后端，切换方便
  3. 内置数据格式转换和质量过滤
  4. 支持分布式执行
```

### 3.2 vLLM 高速推理

```
vLLM 是目前最快的 LLM 推理引擎：

核心技术：PagedAttention
  传统推理：为每个序列预分配固定大小的 KV Cache → 浪费显存
  vLLM：像操作系统管理内存一样，按"页"动态分配 KV Cache
  → 显存利用率提升 2-4 倍，吞吐量提升 10-20 倍

在数据蒸馏中的作用：
  需要对数万道题生成回答，每道题还要生成多个回答
  如果用 transformers 直接推理：可能需要几天
  用 vLLM：几小时就能完成

配置解析：
  tensor_parallel_size=1  → 单卡推理（多卡可设为 2/4/8）
  max_model_len=8192      → 支持的最大序列长度
  temperature=0.6         → 适中的随机性（DeepSeek 推荐值）
  max_new_tokens=8192     → 允许生成很长的推理链
```

### 3.3 num_generations=4 的设计

```
对每道题生成 4 个不同的回答，目的是：

1. 拒绝采样（Rejection Sampling）：
   4 个回答中，可能有的答案正确，有的错误
   只保留答案正确的回答作为训练数据
   → 自动过滤低质量数据

2. 数据增强：
   同一道题的多种正确解法
   → 增加训练数据的多样性
   → Student 学到多种推理路径

3. Best-of-N 选择：
   从 4 个回答中选最好的一个
   → 训练数据质量高于 Teacher 的平均水平

实际流程：
  10 万道题 × 4 个回答 = 40 万条候选数据
  经过拒绝采样过滤 → 约 20-30 万条高质量数据
  用这些数据训练 Student 模型
```

## 第四章：模型蒸馏核心原理

### 4.1 模型蒸馏的整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    模型蒸馏训练架构                               │
│                                                                   │
│  输入：[prompt tokens] [response tokens]                         │
│         │                                                         │
│         ├──────────────────────┐                                 │
│         ▼                      ▼                                 │
│  ┌──────────────┐      ┌──────────────┐                         │
│  │   Student     │      │   Teacher     │                         │
│  │  (训练中)     │      │  (冻结)       │                         │
│  │  Qwen-0.5B   │      │  Qwen-7B     │                         │
│  └──────┬───────┘      └──────┬───────┘                         │
│         │                      │                                  │
│         ▼                      ▼                                  │
│  student_logits          teacher_logits                           │
│  (可训练的分布)          (目标分布)                               │
│         │                      │                                  │
│         │    ┌─────────────────┘                                 │
│         │    │                                                    │
│         ▼    ▼                                                    │
│  ┌─────────────────────────────────────┐                         │
│  │  损失函数：                          │                         │
│  │  L = α × CE(student, labels)        │  ← SFT 损失            │
│  │    + (1-α) × KL(student || teacher) │  ← 蒸馏损失            │
│  └─────────────────────────────────────┘                         │
│         │                                                         │
│         ▼                                                         │
│  更新 Student 参数                                                │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 为什么只对 response 部分计算蒸馏损失？

```
输入序列结构：
  [system prompt] [user question] [assistant response]
  ←────── prompt 部分 ──────→ ←── response 部分 ──→

只对 response 部分计算损失的原因：
  1. prompt 部分是固定的输入，不需要模型"学习"如何生成
  2. 我们只关心模型的"回答能力"，不关心它如何复述问题
  3. 如果对 prompt 也计算损失，会浪费训练资源在无意义的目标上

代码实现：
  prompt_lengths = inputs["prompts"].shape[1]
  shifted_student_logits = outputs_student.logits[:, prompt_lengths-1:-1, :]
  shifted_teacher_logits = outputs_teacher.logits[:, prompt_lengths-1:-1, :]

  为什么是 prompt_lengths-1？
    因为语言模型的 logits[i] 预测的是 token[i+1]
    所以 logits[prompt_length-1] 预测的是第一个 response token
```

## 第五章：蒸馏损失函数详解

### 5.1 损失函数公式

```
总损失 = α × L_SFT + (1-α) × L_KL × T²

其中：
  L_SFT = CrossEntropy(student_logits, labels)
    标准的交叉熵损失，让 Student 生成正确的文本

  L_KL = KL(log_softmax(student_logits/T) || softmax(teacher_logits/T))
    KL 散度损失，让 Student 的概率分布接近 Teacher

  T = temperature（温度系数）
  α = alpha（权重系数）
  T² = 温度补偿因子
```

### 5.2 KL 散度直觉理解

```
KL 散度衡量两个概率分布的"距离"：

  KL(P || Q) = Σ P(x) × log(P(x) / Q(x))

  KL = 0  → 两个分布完全相同
  KL > 0  → 分布有差异（KL 越大差异越大）

在蒸馏中：
  P = Student 的分布（要被优化的）
  Q = Teacher 的分布（目标）

  优化目标：最小化 KL(Student || Teacher)
  → 让 Student 的输出分布尽可能接近 Teacher

注意：KL 散度不对称！
  KL(P||Q) ≠ KL(Q||P)
  KL(Student||Teacher)：Student 在 Teacher 概率高的地方也要高
  → 这种方向更适合蒸馏（Student 学习 Teacher 的"重点"）
```

### 5.3 温度补偿因子 T² 的作用

```
为什么要乘以 T²？

数学推导：
  softmax(z/T) 的梯度 ∝ 1/T²
  当 T > 1 时，梯度被缩小了 T² 倍
  如果不补偿，蒸馏损失的梯度会远小于 SFT 损失
  → 蒸馏信号被淹没，等于没有蒸馏

乘以 T² 后：
  蒸馏损失的梯度量级恢复正常
  可以与 SFT 损失公平竞争
  α 参数才能真正控制两者的比例

这是 Hinton 2015 原论文中的重要技巧，很多实现会遗漏。
```

### 5.4 alpha 参数的影响

```
alpha 控制 SFT 和蒸馏的权重比例：

alpha = 1.0（纯 SFT）：
  L = 1.0 × L_SFT + 0.0 × L_KL
  完全忽略 Teacher 的 logits
  退化为普通的 SFT 训练
  适用场景：Teacher 和 Student 架构差异太大

alpha = 0.5（均衡）：
  L = 0.5 × L_SFT + 0.5 × L_KL
  两种信号各占一半
  Hinton 原论文推荐的设置

alpha = 0.0（纯蒸馏）：
  L = 0.0 × L_SFT + 1.0 × L_KL
  完全依赖 Teacher 的分布
  风险：如果 Teacher 在某些样本上不确定，Student 也会学到不确定性

本脚本 alpha=1：
  当前配置是纯 SFT（蒸馏损失权重为 0）
  这可能是调试阶段的设置
  实际训练建议 alpha=0.5~0.7
```

## 第六章：训练参数详解

### 6.1 DistillConfig 参数

```python
training_args = DistillConfig(
    # ---- 蒸馏特有参数 ----
    temperature=0.9,          # 软化温度
    alpha=1,                  # SFT 损失权重（1-alpha 为蒸馏权重）
    max_new_tokens=1024,      # Teacher 生成最大长度

    # ---- 常规训练参数 ----
    learning_rate=1e-5,
    warmup_ratio=0.1,
    lr_scheduler_type="cosine",
    num_train_epochs=4,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=16,
    bf16=True,
)
```

| 参数 | 值 | 含义 | 调参建议 |
|------|-----|------|---------|
| `temperature` | 0.9 | 软化 logits 的温度 | 1~5 之间尝试，越大暗知识越多 |
| `alpha` | 1.0 | SFT 损失权重 | 建议 0.5~0.7 |
| `max_new_tokens` | 1024 | 推理链最大长度 | 根据任务调整 |
| `learning_rate` | 1e-5 | 学习率 | 蒸馏通常用较小学习率 |
| `num_train_epochs` | 4 | 训练轮数 | 蒸馏数据质量高，可以多训几轮 |
| `gradient_accumulation_steps` | 16 | 梯度累积 | 等效 batch=64 |

### 6.2 显存分析

```
模型蒸馏的显存需求（Qwen2.5-0.5B 作为 Student 和 Teacher）：

Student 模型（训练模式）：
  参数：~1 GB（bfloat16）
  梯度：~1 GB
  优化器状态：~2 GB（AdamW）
  激活值：~1-2 GB

Teacher 模型（推理模式）：
  参数：~1 GB（bfloat16）
  激活值：~0.5 GB（no_grad，不保存中间激活）

总计：~6-8 GB（0.5B + 0.5B 的演示配置）

实际蒸馏（7B Teacher + 0.5B Student）：
  Teacher：~14 GB
  Student：~4 GB
  总计：~20-25 GB → 需要较大显存的 GPU

优化策略：
  1. Teacher 使用 Flash Attention 2（本脚本已使用）
  2. gradient_checkpointing 减少激活值显存
  3. DeepSpeed ZeRO 分片（本脚本支持）
```

### 7.2 数据格式转换

```python

#          {"role": "user", "content": "1+1=?"},
#          {"role": "assistant", "content": "<think>...</think>答案是2"}
#        ]}

# DataCollatorForChatML 进一步处理：
# 1. 用 tokenizer 的 chat_template 将 messages 转为 token ids
# 2. 生成 labels（prompt 部分设为 -100，只对 response 计算损失）
# 3. 生成 prompts 字段（用于确定 prompt 长度，截取 response logits）
```

### 7.3 DistillTrainer 的核心 compute_loss

```python
def compute_loss(self, model, inputs, return_outputs=False):
    # 步骤 1：Student 前向传播（计算梯度）
    outputs_student = model(input_ids=..., attention_mask=..., labels=...)
    student_loss = outputs_student.loss  # 交叉熵损失

    # 步骤 2：Teacher 前向传播（不计算梯度）
    with torch.no_grad():
        outputs_teacher = self.teacher_model(input_ids=..., attention_mask=...)

    # 步骤 3：截取 response 部分的 logits
    prompt_lengths = inputs["prompts"].shape[1]
    shifted_student_logits = outputs_student.logits[:, prompt_lengths-1:-1, :]
    shifted_teacher_logits = outputs_teacher.logits[:, prompt_lengths-1:-1, :]

    # 步骤 4：计算 KL 散度蒸馏损失
    loss_logits = KLDivLoss(
        log_softmax(student_logits / T),   # Student: 对数概率
        softmax(teacher_logits / T),       # Teacher: 概率
    ) * T²                                 # 温度补偿

    # 步骤 5：加权合并
    loss = α × student_loss + (1-α) × loss_logits
    return loss
```

### 7.4 DeepSpeed 适配

```
DistillTrainer 支持 DeepSpeed 多卡训练：

ZeRO-3 模式：
  Student 和 Teacher 的参数都分片到多个 GPU
  每个 GPU 只保存部分参数
  前向传播时动态收集需要的参数
  → 可以训练超大模型

非 ZeRO-3 模式：
  Teacher 使用 ZeRO-0（每个 GPU 保留完整副本）
  因为 Teacher 不需要训练，不需要分片优化器状态
  → 简单高效

_prepare_deepspeed 方法的作用：
  根据当前 DeepSpeed 配置，正确初始化 Teacher 模型
  确保 Teacher 在多卡环境下能正常推理
```

## 附录：常见问题

### Q1：数据蒸馏和模型蒸馏选哪个？

```
决策树：

Teacher 能否与 Student 同时加载到 GPU？
  ├── 能 → 模型蒸馏（效果更好）
  └── 不能 → 数据蒸馏（分两步进行）

Teacher 和 Student 的词表是否相同？
  ├── 相同 → 模型蒸馏可行
  └── 不同 → 只能用数据蒸馏（logits 维度不匹配）

实际建议：
  资源充足 → 先数据蒸馏 SFT，再模型蒸馏微调（效果最好）
  资源有限 → 只做数据蒸馏 SFT（简单有效）
```

### Q2：temperature 设多少合适？

```
不同场景的推荐值：

数学推理蒸馏：T = 1~2
  推理任务答案比较确定，不需要太多"暗知识"
  T 太大反而会引入噪声

通用对话蒸馏：T = 3~5
  对话任务有很多合理的回答方式
  需要更多暗知识来传递"哪些回答也可以"

代码生成蒸馏：T = 1~3
  代码有一定的确定性，但也有多种写法
  适中的温度即可

Hinton 原论文：T = 4~10
  在图像分类任务上的推荐值
  NLP 任务通常不需要这么高
```

可以！这正是 DeepSeek-R1 的完整路线：

完整流程：

### Q5：DataCollatorForChatML 做了什么？

```
DataCollatorForChatML 是 TRL 库提供的数据整理器：

输入：{"messages": [{"role": "user", ...}, {"role": "assistant", ...}]}

处理步骤：
  1. 用 tokenizer 的 chat_template 将 messages 转为 token 序列
     → "<|im_start|>user\n问题<|im_end|>\n<|im_start|>assistant\n回答<|im_end|>"

  2. 生成 labels：
     prompt 部分（user 消息）→ 设为 -100（不计算损失）
     response 部分（assistant 消息）→ 保留原始 token id

  3. 生成 prompts 字段：
     只包含 prompt 部分的 token ids
     用于 compute_loss 中确定从哪里开始截取 response logits

  4. padding 和 truncation：
     按 max_seq_length 截断，按 batch 内最长序列 padding

输出：{"input_ids", "attention_mask", "labels", "prompts"}
```

### Q6：蒸馏和 SFT 有什么本质区别？

```
表面上看，蒸馏和 SFT 都是"让模型学习生成特定文本"。
但本质区别在于学习信号的丰富程度：

SFT 的学习信号：
  对于每个位置，只有一个正确答案（one-hot 标签）
  "这个位置应该生成 token X"
  信息量：log(vocab_size) bits ≈ 17 bits

蒸馏的学习信号：
  对于每个位置，有完整的概率分布（soft label）
  "这个位置生成 X 的概率是 0.6，Y 是 0.2，Z 是 0.1..."
  信息量：vocab_size × entropy bits >> 17 bits

类比：
  SFT = 只告诉学生"正确答案是 A"
  蒸馏 = 告诉学生"A 最可能(60%)，B 也有道理(20%)，C 勉强(10%)，D 不对(1%)"

后者传递了更多关于"为什么"的信息。
```
