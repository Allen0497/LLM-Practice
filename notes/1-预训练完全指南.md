## 第零章：大模型训练的全景图

在深入预训练之前，先看一下训练一个大模型的**完整流程**，这样你能知道我们现在处于哪个阶段：

```
┌─────────────────────────────────────────────────────────────────────┐
│                     大模型训练完整流程                                │
│                                                                     │
│   ① 预训练（Pre-Training）       ← 📍 我们现在在这里！              │
│   │  让模型阅读海量文本，学会语言的基本规律                           │
│   │  输入：海量纯文本（几十GB～几TB）                                │
│   │  输出：一个"什么都知道一点，但什么都不精"的基座模型               │
│   │                                                                 │
│   ② 指令微调（SFT, Supervised Fine-Tuning）                        │
│   │  用"问题-回答"格式的数据教模型如何对话                           │
│   │  输入：指令数据集（"请帮我写一首诗" → "春风又绿江南岸..."）      │
│   │  输出：一个会对话的模型                                          │
│   │                                                                 │
│   ③ 偏好对齐（RLHF / DPO / GRPO 等）                               │
│   │  让模型的回答更符合人类偏好（更有帮助、更安全）                   │
│   │  输入：人类偏好数据（好回答 vs 坏回答）                          │
│   │  输出：一个回答质量更高的模型                                    │
│   │                                                                 │
│   ④ 评估与部署                                                      │
│      用标准测试集评估模型能力，然后部署上线                           │
└─────────────────────────────────────────────────────────────────────┘
```

**打个比方：**

| 阶段 | 类比 | 做什么 |
|------|------|--------|
| 预训练 | 上学读书12年 | 博览群书，学习语言和知识 |
| 指令微调 | 岗前培训 | 学会按要求完成具体任务 |
| 偏好对齐 | 职业素养训练 | 学会什么该说什么不该说 |

本文档聚焦的就是 **第①步：预训练**。

## 第一章：什么是预训练？为什么需要预训练？

### 1.1 预训练的核心思想：预测下一个字

预训练的学习方式极其简单 —— **给模型看一段文字的前半部分，让它猜下一个字是什么**。

```
输入：  "今 天 天 气"
目标：  预测下一个字 → "很" ✓  "是" ✗  "猫" ✗
```

这就叫 **"自回归语言建模"（Causal Language Modeling, CLM）**，也叫 **Next Token Prediction**。

看起来很简单对吧？但当你用**几TB的文本**、**数十亿个参数**的模型来做这件事时，模型为了能准确预测下一个字，就不得不学会：

- **语法**：主语后面通常跟动词
- **语义**：理解"银行"在"河岸"和"金融机构"两种语境中的不同含义
- **知识**：知道"地球绕着太阳转"、"水的化学式是H2O"
- **推理**：如果"所有人都会死"且"苏格拉底是人"，那么...

### 1.2 为什么叫"预"训练？

因为这只是第一步。预训练完成后，模型学会了语言能力，但还不会按你的指令干活。
就像一个读了很多书的人，知识很渊博，但你问他"帮我写个邮件"，他可能会接着你的话继续胡扯，而不是真的帮你写邮件。

所以后面还需要"指令微调"来教它干活。

### 1.3 从零预训练 vs 加载已有模型

我们这个项目做的是**从零开始预训练**（from scratch）：

```python
# ❌ 这是加载已经训练好的模型（用于微调或推理）
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B")

# ✅ 这是从零开始，随机初始化一个新模型（用于预训练）
config = AutoConfig.from_pretrained("models/Qwen2.5-0.5B")
model = AutoModelForCausalLM.from_config(config)
```

区别是什么？
- `from_pretrained`：下载别人训练好的模型权重（参数已经学过东西了）
- `from_config`：只用模型的"建筑图纸"（架构配置），权重全部随机初始化（参数是乱的，啥都不知道）

我们用 `from_config` 是因为我们想从零学习预训练过程，亲自训练一个模型出来。

## 第二章：我们要训练的模型 —— Qwen2.5-0.5B 架构详解

### 2.1 模型是什么？

你可以把大语言模型想象成一个**巨大的函数**：

```
输入：一串数字（代表文字）  →  [模型（一堆参数）]  →  输出：下一个数字的概率分布
```

模型内部是一堆**参数（权重）**，预训练就是不断调整这些参数，让模型的预测越来越准。

### 2.2 Transformer 架构 —— 大模型的骨架

几乎所有大模型（GPT、Qwen、LLaMA、DeepSeek...）都基于 **Transformer** 架构。
Qwen2.5 用的是 **Decoder-Only Transformer**（只有解码器的 Transformer），核心组件如下：

```
┌────────────────────────────────────────────────────┐
│              Qwen2.5-0.5B 模型结构                  │
│                                                    │
│  输入 Token IDs: [1234, 5678, 9012, ...]           │
│       ↓                                            │
│  ┌─────────────────────────────┐                   │
│  │  Embedding 层（词嵌入）      │ 把数字映射成向量   │
│  │  vocab_size=151936          │ 15万词 → 896维向量 │
│  │  hidden_size=896            │                   │
│  └─────────────┬───────────────┘                   │
│                ↓                                    │
│  ┌─────────────────────────────┐                   │
│  │  Transformer Block × 24     │ 重复堆叠24层      │
│  │  ┌───────────────────────┐  │                   │
│  │  │ ① 自注意力(Attention) │  │ 让每个字"看到"     │
│  │  │   14个注意力头         │  │ 前面所有字的信息   │
│  │  │   2个KV头(GQA)        │  │                   │
│  │  ├───────────────────────┤  │                   │
│  │  │ ② FFN (前馈网络)      │  │ 对信息做非线性变换 │
│  │  │   中间维度=4864        │  │                   │
│  │  ├───────────────────────┤  │                   │
│  │  │ ③ RMSNorm (归一化)    │  │ 稳定训练过程       │
│  │  └───────────────────────┘  │                   │
│  └─────────────┬───────────────┘                   │
│                ↓                                    │
│  ┌─────────────────────────────┐                   │
│  │  输出层 (LM Head)           │ 896维 → 15万维    │
│  │  预测下一个token的概率       │ 每个词的概率       │
│  └─────────────────────────────┘                   │
└────────────────────────────────────────────────────┘
```

### 2.3 config.json —— 模型的建筑图纸

这些架构信息都记录在 `models/Qwen2.5-0.5B/config.json` 中：

```json
{
  "hidden_size": 896,           // 隐藏层维度：每个 token 用 896 个数字表示
  "num_hidden_layers": 24,      // Transformer 层数：堆叠 24 层
  "num_attention_heads": 14,    // 注意力头数：14 个头并行做注意力计算
  "num_key_value_heads": 2,     // KV 头数：使用 GQA（分组查询注意力）节省显存
  "intermediate_size": 4864,    // FFN 中间维度
  "vocab_size": 151936,         // 词表大小：约 15 万个 token
  "max_position_embeddings": 32768,  // 最大上下文长度：32K
  "hidden_act": "silu",        // 激活函数：SiLU
  "rope_theta": 1000000.0,     // RoPE 位置编码的 theta 参数
  "rms_norm_eps": 1e-06,       // RMSNorm 的 epsilon
  "tie_word_embeddings": true   // 输入 Embedding 和输出 LM Head 共享权重
}
```

**关键参数解读：**

| 参数 | 值 | 通俗解释 |
|------|----|----------|
| `hidden_size` | 896 | 模型"思考"的维度。越大模型越聪明，但也越大 |
| `num_hidden_layers` | 24 | 模型"思考"的深度。越多层，理解能力越强 |
| `num_attention_heads` | 14 | 模型同时从几个角度"看"文本 |
| `num_key_value_heads` | 2 | GQA 技术：14 个注意力头共享 2 组 KV，大幅节省显存 |
| `vocab_size` | 151936 | 模型认识多少个不同的 token（字/词/子词） |

### 2.4 模型有多大？

Qwen2.5-**0.5B** 表示模型约有 **5 亿个参数**。对比一下：

| 模型 | 参数量 | 类比 |
|------|--------|------|
| 我们的 Qwen2.5-0.5B | 5 亿 | 小学生 |
| Qwen2.5-7B | 70 亿 | 大学生 |
| Qwen2.5-72B | 720 亿 | 博士 |
| GPT-4 (估计) | ~1.8 万亿 | 教授团队 |

0.5B 是一个非常适合学习的大小：训练速度快、显存占用小、能在单卡上跑。

## 第三章：数据准备 —— 模型的"教科书"

### 3.1 预训练需要什么样的数据？

预训练数据就是**大量的纯文本**，没有标注、没有问答格式，就是原始的文章、网页、书籍等。

我们用的数据来�� **BAAI/IndustryCorpus2**（北京智源研究院行业语料库），选了 3 个行业：

| 行业 | 目录名 | 内容举例 |
|------|--------|----------|
| 影视娱乐 | `film_entertainment` | 电影评论、娱乐新闻、剧情简介 |
| 文学情感 | `literature_emotion` | 小说、散文、诗歌、情感文章 |
| 新闻媒体 | `news_media` | 新闻报道、时事评论 |

每个行业下面有中文（chinese）和英文（english）子目录，我们只用了 `high` 质量的数据。

### 3.2 数据长什么样？

数据是 `.parquet` 格式（一种高效的列式存储格式），每条数据很简单，就一个 `text` 字段：

```
┌──────────────────────────────────────────────────────┐
│ text                                                 │
├──────────────────────────────────────────────────────┤
│ "《流浪地球》是中国科幻电影的里程碑之作，影片讲述了..." │
│ "近日，国际油价持续走低，分析人士指出..."              │
│ "春风又绿江南岸，明月何时照我还..."                    │
│ ...                                                  │
└──────────────────────────────────────────────────────┘
```

### 3.3 数据是怎么下载的？

通过 `download_data.sh` 脚本，用 ModelScope 命令行工具下载：

```bash
# 下载影视娱乐领域的高质量数据
modelscope download --dataset 'BAAI/IndustryCorpus2' \
    --include 'film_entertainment/*/high*' \
    --local_dir 'data/pt'

# 英文数据太多，只保留前3个文件
find 'data/pt/film_entertainment/english/high' -maxdepth 1 -type f | sort | tail -n +4 | xargs rm -f
```

- `--include 'film_entertainment/*/high*'`：只下载 `high` 质量的文件（`*` 是通配符，匹配 chinese 和 english）
- 英文数据文件较多，脚本下载完后删除多余的，只保留前 3 个

### 3.4 数据存放结构

```
data/pt/
├── film_entertainment/          ← 影视娱乐
│   ├── chinese/high/            ← 中文高质量
│   │   ├── rank_00042.parquet
│   │   ├── rank_00043.parquet
│   │   └── rank_00044.parquet
│   └── english/high/            ← 英文高质量（只留3个）
│       ├── rank_00961.parquet
│       ├── rank_00962.parquet
│       └── rank_00963.parquet
├── literature_emotion/          ← 文学情感
│   ├── chinese/high/
│   └── english/high/
└── news_media/                  ← 新闻媒体
    ├── chinese/high/
    └── english/high/
```

共 **21 个 parquet 文件**，约 **13 GB**。

### 3.5 代码中是怎么加载数据的？

```python
# 步骤一：列出要用的三个行业目录
directories = ["film_entertainment", "literature_emotion", "news_media"]

# 步骤二：找到所有 .parquet 文件路径
data_files = find_files(directories)  # 返回 21 个文件路径的列表

# 步骤三：用 HuggingFace datasets 加载
dataset = load_dataset(
    "parquet",              # 数据格式
    data_files=data_files,  # 文件列表
    split="train",          # 作为训练集
    columns=["text"],       # 只要 text 列
    cache_dir=TMP_PATH      # 缓存目录
)

# 步骤四：打乱顺序（很重要！）
dataset = dataset.shuffle(seed=42)
```

**为什么要打乱（shuffle）？**

如果不打乱，模型会先学完所有影视数据，再学文学，再学新闻。这会导致**灾难性遗忘** —— 学到后面把前面学的忘了。打乱后三个领域的数据混在一起，模型能均匀地学习。

## 第四章：分词器（Tokenizer）—— 把人话翻译成数字

### 4.1 为什么需要分词器？

计算机不认识文字，只认识数字。分词器就是**文字和数字之间的翻译官**。

```
"今天天气真好" → 分词器 → [108386, 104165, 37029, 16791]
```

### 4.2 什么是 Token？

Token 不完全等于"字"或"词"，它是分词器把文本切分出的**最小单元**。

Qwen 使用 **BPE (Byte Pair Encoding)** 算法，它会根据统计频率，把常见的字符组合合并成一个 token：

```
"预训练" → 可能切成 ["预训", "练"]  （2个token）
"Hello"  → 可能就是 ["Hello"]       （1个token）
"Pneumonoultramicroscopicsilicovolcanoconiosis"
         → 会切成很多小块             （很多token）
```

**核心思想**：常见的词/短语 → 少量 token，罕见的词 → 拆成多个 token。

### 4.3 Qwen 的词表

```python
tokenizer = AutoTokenizer.from_pretrained("models/Qwen2.5-0.5B")
print(len(tokenizer))  # 151936 —— 约 15 万个 token
```


这 15 万个 token 就像字典里的"词条"，包括：
- 中文常见字词：`的`、`是`、`不`、`你好`、`中国`...
- 英文单词和子词：`the`、`ing`、`tion`、`Hello`...
- 特殊标记：`<|im_start|>`（对话开始）、`<|im_end|>`（对话结束）、`<|endoftext|>`（文本结束）等

特殊标记在训练中有重要作用，比如 `<|im_end|>` 在我们的预训练代码中被用作**文档分隔符**，告诉模型"这篇文章到此结束了"。

### 4.4 代码中的分词过程

```python
# 加载分词器
tokenizer = AutoTokenizer.from_pretrained("models/Qwen2.5-0.5B")

# 分词示例
text = "今天天气真好"
tokens = tokenizer(text)
# tokens["input_ids"] = [108386, 104165, 37029, 16791]
# tokens["attention_mask"] = [1, 1, 1, 1]
```

返回两个东西：
- `input_ids`：每个 token 对应的数字编号
- `attention_mask`：全是 1，表示"这些位置都是有效的"（后面 padding 的位置会是 0）

### 4.5 为什么每篇文章末尾要加 `<|im_end|>`？

在 `tokenize_dataset()` 函数中：

```python
eos_token = "<|im_end|>"
text_examples = [text + eos_token for text in examples["text"]]
```

这是因为预训练时会把多篇文章**拼接**在一起（下一章详细讲）。如果不加分隔符，模型会以为两篇不相关的文章是连续的，学到错误的关联。

```
没有分隔符（错误）：
"...电影票房大卖。近日国际油价持续走低..."
→ 模型可能学到"票房大卖"和"油价走低"有关联 ❌

有分隔符（正确）：
"...电影票房大卖。<|im_end|>近日国际油价持续走低..."
→ 模型知道这是两篇不同的文章 ✓
```

## 第五章：数据预处理 —— 拼接与分块

### 5.1 为什么要拼接和分块？

原始数据中，每篇文章长短不一：有的只有 50 个 token，有的有 5000 个 token。

如果直接用原始文章训练，会有两个问题：

| 问题 | 说明 |
|------|------|
| 短文章浪费算力 | 一篇 50 token 的文章，要 padding 到 512，462 个位置全是空的 |
| 长文章放不下 | 一篇 5000 token 的文章超过了我们设定的 512 长度 |

**解决方案：拼接 + 分块**

把所有文章首尾相连拼成一条超长的 token 序列，然后按固定长度（512）切块。

### 5.2 图解拼接与分块过程

```
原始文章（分词后）：
  文章A: [101, 202, 303, EOS]           (4 tokens)
  文章B: [404, 505, 606, 707, 808, EOS] (6 tokens)
  文章C: [909, 111, 222, EOS]           (4 tokens)
  （EOS = <|im_end|> 的 token id）

第一步：拼接成一条长序列
  [101, 202, 303, EOS, 404, 505, 606, 707, 808, EOS, 909, 111, 222, EOS]
  总长度 = 14 tokens

第二步：按 block_size=5 切块（实际代码中是 512，这里用 5 举例）
  块1: [101, 202, 303, EOS, 404]   ← 包含文章A的结尾和文章B的开头
  块2: [505, 606, 707, 808, EOS]   ← 文章B的剩余部分
  丢弃: [909, 111, 222, EOS]       ← 不足 5 个，丢弃（只损失很少数据）
```

### 5.3 `tokenize_dataset()` 函数详解

这个函数在 `utils/utils.py` 中，是数据预处理的核心：

```python
def tokenize_dataset(examples, tokenizer, block_size=512):
    # 第一步：给每篇文章末尾加上结束符
    eos_token = "<|im_end|>"
    text_examples = [text + eos_token for text in examples["text"]]

    # 第二步：分词（把文字变成数字）
    # add_special_tokens=False 表示不自动添加额外的特殊标记
    tokenized_examples = tokenizer(text_examples, add_special_tokens=False)

    # 第三步：拼接所有文章的 token
    # chain(*lists) 把多个列表首尾相连
    # 例如：chain([1,2], [3,4], [5,6]) → [1,2,3,4,5,6]
    concatenated_examples = {
        k: list(chain(*tokenized_examples[k]))
        for k in tokenized_examples.keys()
    }

    # 第四步：计算能切出多少个完整的块
    total_length = len(concatenated_examples["input_ids"])
    total_length = (total_length // block_size) * block_size
    # 例如：总共 10000 个 token，block_size=512
    # 10000 // 512 = 19 个完整块，19 * 512 = 9728
    # 末尾 272 个 token 被丢弃（损失很小）

    # 第五步：切块
    result = {
        k: [t[i : i + block_size] for i in range(0, total_length, block_size)]
        for k, t in concatenated_examples.items()
    }
    return result, total_length
```

### 5.4 `dataset.map()` —— 批量处理的引擎

```python
train_dataset = dataset.map(
    map_callback,           # 处理函数
    batched=True,           # 批量模式：一次传入多条数据
    batch_size=5000,        # 每批 5000 条原始文章
    remove_columns=dataset.column_names,  # 删除原始的 "text" 列
    num_proc=32,            # 32 个进程并行处理
)
```

**为什么用 `batched=True`？**

如果不用批量模式，每次只处理一篇文章，短文章切不出一个完整的 512 块就被丢弃了，浪费严重。批量模式下，5000 篇文章的 token 拼在一起再切块，利用率接近 100%。

### 5.5 处理后的数据长什么样？

```
处理前（原始数据集）：
  {"text": "今天天气真好..."}
  {"text": "电影票房大卖..."}
  ...

处理后（训练数据集）：
  {"input_ids": [108386, 104165, ..., 共512个], "attention_mask": [1, 1, ..., 共512个]}
  {"input_ids": [37029, 16791, ..., 共512个], "attention_mask": [1, 1, ..., 共512个]}
  ...
```

每条数据都是整整齐齐的 512 个 token，没有 padding，不浪费一丝算力。

### 5.6 数据缓存机制

```python
tokenized_datapath = os.path.join(DATA_PATH, "tokenized_dataset")

if not os.path.isdir(tokenized_datapath):
    # 第一次运行：处理数据并保存

    train_dataset.save_to_disk(tokenized_datapath)

```

数据预处理可能需要几十分钟，但只需要做一次。处理好的数据保存到磁盘后，下次训练直接加载，非常高效。

## 第六章：训练超参数 —— 控制模型怎么学

超参数就是训练前人为设定的参数，它们决定了模型"怎么学"。就像老师制定学习计划：每天学多少、学多快、复习几遍。

### 6.1 学习率（Learning Rate）

```python
learning_rate=1e-5   # 即 0.00001
```

学习率是最重要的超参数，它控制每次参数更新的**步幅大小**。

```
学习率太大（比如 0.1）：
  参数更新幅度太大，模型在最优解附近来回震荡，永远找不到最优解
  就像下山时步子太大，一脚迈过了山谷，跑到对面山坡上去了

学习率太小（比如 0.0000001）：
  参数更新幅度太小，训练极其缓慢
  就像下山时每步只挪 1 毫米，天黑了还没到山脚

学习率合适（比如 1e-5）：
  稳步下降，最终收敛到一个好的解
```

### 6.2 学习率预热（Warmup）

```python
warmup_ratio=0.1   # 前 10% 的训练步数做预热
```

训练刚开始时，模型参数是随机的，梯度可能非常大。如果一上来就用全速学习率，模型可能直接"崩溃"（loss 变成 NaN）。

预热策略：前 10% 的步数中，学习率从 0 **线性增长**到设定值，让模型先"热热身"。

```
学习率变化曲线（warmup + cosine）：

学习率
  ↑
  |      /‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\
  |     /                          \
  |    /                            \
  |   /                              \
  |  /                                \
  | /                                  \
  |/                                    \___
  +──────────────────────────────────────────→ 训练步数
  0   10%                                100%
     ↑预热阶段        余弦退火阶段→
```

### 6.3 学习率调度器（LR Scheduler）

```python
lr_scheduler_type="cosine"   # 余弦退火
```

预热结束后，学习率按照**余弦曲线**平滑下降，最终接近 0。

为什么要降低学习率？训练初期需要大步探索，后期需要小步精调。就像画画：先用大笔刷铺底色，再用细笔描细节。

### 6.4 训练轮数（Epochs）

```python
num_train_epochs=3   # 整个数据集过 3 遍
```

一个 epoch = 模型把所有训练数据看一遍。3 个 epoch 就是看 3 遍。

为什么要看多遍？就像复习课本，看一遍记不住，多看几遍理解更深。但也不能看太多遍，否则模型会"死记硬背"（过拟合）。

### 6.5 批大小与梯度累积

```python
per_device_train_batch_size=24    # 每张 GPU 每次处理 24 个样本
gradient_accumulation_steps=16    # 累积 16 次梯度后再更新参数
```

**Batch Size（批大小）**：每次送入模型的样本数量。

**为什么不能一次只送 1 个样本？**
- 1 个样本的梯度噪声太大，参数更新方向不稳定
- 多个样本的梯度取平均，方向更准确

**为什么不能一次送很多样本？**
- 显存放不下！24 个样本 × 512 token 已经占了不少显存

**梯度累积的妙用：**

显存不够但想要大 batch 的效果？用梯度累积！

```
正常训练（batch_size=384，显存不够！）：
  送入 384 个样本 → 计算梯度 → 更新参数

梯度累积（batch_size=24, accumulation=16）：
  送入 24 个样本 → 计算梯度 → 先存着不更新
  送入 24 个样本 → 计算梯度 → 累加到之前的梯度上
  ... 重复 16 次 ...
  16 次梯度累加完毕 → 更新参数

效果等价于 batch_size = 24 × 16 = 384，但显存只需要放 24 个样本！
```

### 6.6 混合精度训练（BF16）

```python
bf16=True   # 使用 BFloat16 半精度
```

计算机中数字的精度：
- FP32（单精度）：32 位，精度高但占空间大
- BF16（半精度）：16 位，精度略低但占空间减半

```
FP32: 占 4 字节/参数  →  5亿参数 × 4B = 2GB 显存
BF16: 占 2 字节/参数  →  5亿参数 × 2B = 1GB 显存
```

BF16 相比 FP16 的优势：数值范围更大，训练更稳定，不容易出现数值溢出。现代 GPU（A100/H100 等）都原生支持 BF16。

### 6.7 梯度检查点（Gradient Checkpointing）

```python
gradient_checkpointing=True   # 用时间换空间
```

正常训练时，前向传播的所有中间结果都要保存在显存中（反向传播时需要用到）。24 层 Transformer 的中间结果非常占显存。

开启梯度检查点后：
- 只保存部分层的中间结果
- 反向传播时，需要哪层的结果就重新计算哪层
- 显存占用大幅减少（约 60-70%）
- 代价：训练速度慢约 20-30%（因为要重新计算）

对于显存紧张的情况，这是非常值得的交换。

### 6.8 检查点保存

```python
save_steps=10_000      # 每 10000 步保存一次
save_total_limit=3     # 最多保留 3 个检查点
```

训练可能需要几天甚至几周。如果中途断电或出错，没有检查点就要从头来过。检查点就是训练过程中的"存档"，可以从断点继续训练。

只保留 3 个是为了节省磁盘空间（每个检查点约 1-2 GB）。

### 6.9 超参数总览表

| 超参数 | 值 | 作用 | 类比 |
|--------|-----|------|------|
| `learning_rate` | 1e-5 | 每步学多少 | 下山的步幅 |
| `warmup_ratio` | 0.1 | 开头慢慢加速 | 热身运动 |
| `lr_scheduler_type` | cosine | 后期逐渐减速 | 先快后慢 |
| `num_train_epochs` | 3 | 数据看几遍 | 复习次数 |
| `per_device_train_batch_size` | 24 | 每次看几个样本 | 每次做几道题 |
| `gradient_accumulation_steps` | 16 | 攒几次梯度再更新 | 攒够作业一起交 |
| `bf16` | True | 半精度省显存 | 用铅笔而非钢笔 |
| `gradient_checkpointing` | True | 时间换空间 | 不记笔记，需要时翻书 |

## 第七章：训练过程 —— 模型到底在干什么

这一章是核心中的核心。我们来看模型训练时，每一步到底发生了什么。

### 7.1 训练循环的全貌

```python
# Trainer.train() 内部的简化逻辑：
for epoch in range(3):                          # 3 个 epoch
    for step, batch in enumerate(dataloader):    # 遍历每个 batch
        # 1. 前向传播：模型预测
        outputs = model(batch["input_ids"])
        loss = outputs.loss

        # 2. 反向传播：计算梯度
        loss.backward()

        # 3. 参数更新（每 16 步才真正更新一次）
        if (step + 1) % 16 == 0:
            optimizer.step()        # 更新参数
            scheduler.step()        # 更新学习率
            optimizer.zero_grad()   # 清零梯度
```

### 7.2 第一步：前向传播（Forward Pass）

模型接收一个 batch 的 input_ids，经过层层计算，输出每个位置上"下一个 token 是什么"的概率分布。

```
输入 input_ids: [今, 天, 天, 气, 真, 好]

模型内部处理：
  Embedding层：把每个 token 变成 896 维向量
  ↓
  Transformer Layer 1：自注意力 + FFN
  ↓
  Transformer Layer 2：自注意力 + FFN
  ↓
  ... 共 24 层 ...
  ↓
  Transformer Layer 24：自注意力 + FFN
  ↓
  LM Head：把 896 维向量映射到 151936 维（词表大小）

输出 logits（每个位置的预测概率分布）：
  位置0 "今" → 预测下一个: {天:0.3, 日:0.2, 年:0.1, ...}  正确答案: 天 ✓
  位置1 "天" → 预测下一个: {天:0.2, 气:0.15, 空:0.1, ...} 正确答案: 天 ✓
  位置2 "天" → 预测下一个: {气:0.4, 天:0.1, 空:0.08, ...} 正确答案: 气 ✓
  位置3 "气" → 预测下一个: {很:0.3, 真:0.2, 不:0.15, ...} 正确答案: 真 ✓
  位置4 "真" → 预测下一个: {好:0.5, 的:0.1, 棒:0.08, ...} 正确答案: 好 ✓
```

### 7.3 第二步：计算损失（Loss）

损失函数衡量模型预测得"有多差"。预训练用的是**交叉熵损失（Cross-Entropy Loss）**。

```
对于位置0，模型预测 "天" 的概率是 0.3：
  loss_0 = -log(0.3) = 1.20

如果模型预测 "天" 的概率是 0.9：
  loss_0 = -log(0.9) = 0.11

如果模型预测 "天" 的概率是 0.01：
  loss_0 = -log(0.01) = 4.61
```

规律：**预测越准确（概率越高），loss 越小**。

总 loss = 所有位置的 loss 取平均。训练的目标就是让 loss 越来越小。

```
loss 变化趋势（理想情况）：
  loss
  10 |*
     | *
   8 |  *
     |   *
   6 |    **
     |      **
   4 |        ***
     |           ****
   2 |               ********
     |                       **************
   0 +─────────────────────────────────────→ 训练步数
```

### 7.4 第三步：反向传播（Backward Pass）

反向传播是深度学习的核心算法，它回答一个问题：**每个参数应该往哪个方向调整，才能让 loss 变小？**

```
前向传播（从左到右）：
  输入 → Embedding → Layer1 → Layer2 → ... → Layer24 → LM Head → loss

反向传播（从右到左）：
  loss → LM Head → Layer24 → ... → Layer2 → Layer1 → Embedding
  ↓        ↓         ↓                ↓        ↓         ↓
  计算每个参数的梯度（gradient）= loss 对该参数的偏导数
```

梯度告诉我们：
- **方向**：参数应该增大还是减小
- **大小**：应该调整多少

### 7.5 第四步：参数更新

有了梯度，就可以更新参数了：

```
新参数 = 旧参数 - 学习率 × 梯度
```

这就是**梯度下降**的核心公式。

实际使用的是 **AdamW 优化器**，比普通梯度下降更聪明：
- 为每个参数维护独立的学习率（自适应）
- 考虑梯度的历史信息（动量）
- 正确处理权重衰减（防止参数过大）

### 7.6 Data Collator —— 自动生成标签

```python
collator = DataCollatorForLanguageModeling(tokenizer=tokenizer, mlm=False)
```

这个组件做了一件关键的事：**自动生成 labels**。

对于因果语言模型，labels 就是 input_ids 本身（模型内部会自动做移位）：

```
input_ids: [今, 天, 天, 气, 真, 好]
labels:    [今, 天, 天, 气, 真, 好]  ← 看起来一样

模型内部自动移位后的实际对应关系：
  输入:   今  天  天  气  真
  标签:   天  天  气  真  好
  含义: 看到"今"要预测"天"，看到"今天"要预测"天"...
```

`mlm=False` 表示我们用的是 **CLM（因果语言建模）**，不是 BERT 那种 MLM（掩码语言建模）。

### 7.7 Trainer —— 把一切串起来

```python
trainer = Trainer(
    model=model,                  # 模型
    args=training_args,           # 超参数
    data_collator=collator,       # 数据整理器
    train_dataset=train_dataset,  # 数据集
)
trainer.train()  # 开始训练！
```

Trainer 是 HuggingFace 的高级封装，它帮你处理了：

| 功能 | 说明 |
|------|------|
| 数据加载 | 自动创建 DataLoader，按 batch 送数据 |
| 前向传播 | 调用 model() 计算 loss |
| 反向传播 | 调用 loss.backward() 计算梯度 |
| 梯度累积 | 累积 16 步梯度后再更新 |
| 参数更新 | 调用 optimizer.step() |
| 学习率调度 | 自动执行 warmup + cosine 策略 |
| 混合精度 | 自动管理 BF16 计算 |
| 检查点保存 | 每 10000 步自动保存 |
| 日志记录 | 每 10 步打印 loss，发送到 wandb |
| 多卡训练 | 配合 accelerate 自动分布式 |

```python
tokenizer.save_pretrained(output_path)  # 保存分词器
```

`torch.cuda.empty_cache()` 在训练前清理一次显存缓存，释放数据预处理阶段占用的显存，为训练腾出空间。

## 第九章：动手实践 —— 启动你的第一次预训练

### 9.1 环境准备

**硬件要求：**
- GPU：至少 1 张支持 BF16 的 GPU（如 A100、H100、RTX 3090/4090 等）
- 显存：单卡至少 16GB（开启梯度检查点后 0.5B 模型可以在 16GB 显存上跑）
- 磁盘：至少 50GB 空闲空间（数据 + 模型检查点）

**软件依赖：**

```bash
pip install torch transformers datasets wandb accelerate
```

### 9.2 准备数据

运行数据下载脚本：

```bash
bash download_data.sh
```

下载完成后，`data/pt/` 目录下应该有 3 个行业子目录，共约 21 个 parquet 文件。

### 9.3 准备模型配置

确保 `models/Qwen2.5-0.5B/` 目录下有以下文件：
- `config.json`（模型架构配置）
- `tokenizer.json`（分词器）
- `tokenizer_config.json`（分词器配置）
- 其他分词器相关文件

这些文件可以从 HuggingFace 或 ModelScope 下载：

```bash
# 从 ModelScope 下载（国内推荐）
modelscope download --model 'Qwen/Qwen2.5-0.5B' --local_dir 'models/Qwen2.5-0.5B'
```

注意：我们不需要模型权重文件（`.safetensors`），因为是从零训练。但下载时通常会一起下载，不影响使用。

### 9.4 单卡训练

```bash
CUDA_VISIBLE_DEVICES=0 python qwen_pt.py
```

- `CUDA_VISIBLE_DEVICES=0`：指定使用第 0 号 GPU
- 如果有多张 GPU 但只想用一张，这个环境变量很重要

### 9.5 多卡训练

如果你有多张 GPU，可以用 `accelerate` 进行分布式训练：

```bash
accelerate launch --config_file accelerate_config.yaml qwen_pt.py
```

多卡训练时，数据会自动分配到各张 GPU 上，等效 batch size = 24 × 16 × GPU数量。

### 9.6 训练过程中你会看到什么？

```

  Num examples = 1,234,567
  Num Epochs = 3
  Instantaneous batch size per device = 24
  Total train batch size (w. parallel, distributed & accumulation) = 384
  Gradient Accumulation steps = 16

```

**关键指标解读：**

| 指标 | 含义 | 正常范围 |
|------|------|----------|
| `loss` | 损失值，越小越好 | 开始约 10-12，最终降到 2-4 |
| `lr` | 当前学习率 | 先升后降（warmup + cosine） |
| `step` | 当前训练步数 | 持续增长 |
| `samples/sec` | 每秒处理样本数 | 取决于硬件 |

### 9.7 如何判断训练是否正常？

**正常的信号：**
- loss 持续下降（虽然会有波动，但整体趋势向下）
- 没有 NaN 或 Inf 出现
- GPU 利用率接近 100%

**异常的信号：**
- loss 不降反升 → 学习率可能太大
- loss 变成 NaN → 数值溢出，检查学习率和数据
- loss 降到某个值后不再下降 → 可能需要更多数据或更大模型
- GPU 利用率很低 → 数据加载可能是瓶颈，增加 DataLoader 的 num_workers

### 9.8 训练完成后

训练完成后，`results/pt/` 目录下会有完整的模型文件。你可以：

```python
# 加载你训练好的模型
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained("results/pt")
tokenizer = AutoTokenizer.from_pretrained("results/pt")

# 试试让它生成文本
input_text = "今天天气"
inputs = tokenizer(input_text, return_tensors="pt")
outputs = model.generate(**inputs, max_new_tokens=50)
print(tokenizer.decode(outputs[0]))
```

注意：预训练模型只会"续写"文本，不会"回答问题"。要让它会对话，还需要进行指令微调（SFT）。

## 附录：常见问题与排错

### Q1：CUDA Out of Memory（显存不足）怎么办？

**方案（按优先级排序）：**

1. 减小 `per_device_train_batch_size`（比如从 24 降到 16 或 8）
2. 确认 `gradient_checkpointing=True` 已开启
3. 减小 `TRUNK_SIZE`（比如从 512 降到 256）
4. 增大 `gradient_accumulation_steps` 以补偿减小的 batch size

### Q2：loss 一直不降怎么办？

- 检查数据是否正确加载（打印几条看看）
- 尝试增大学习率（比如从 1e-5 到 5e-5 或 1e-4）
- 检查数据是否被正确分词（打印 tokenizer 的输出看看）

### Q3：训练速度太慢怎么办？

- 使用多卡训练（accelerate）
- 安装 `flash-attn` 并设置 `attn_implementation="flash_attention_2"`
- 增大 `per_device_train_batch_size`（在显存允许的范围内）
- 增加 DataLoader 的 `num_workers`（在 TrainingArguments 中设置 `dataloader_num_workers`）

### Q4：wandb 登录失败怎么办？

- 方案一：去 [wandb.ai](https://wandb.ai) 注册账号，获取 API key
- 方案二：不用 wandb，把 `WANDB_LOG` 设为 `False`，并把 `report_to` 改为 `"none"`

### Q5：从检查点恢复训练怎么做？

```python
# 方法一：Trainer 自动检测
trainer.train(resume_from_checkpoint=True)

# 方法二：指定检查点路径
trainer.train(resume_from_checkpoint="results/pt/checkpoint-10000")
```

### Q6：怎么知道模型训练得好不好？

预训练阶段主要看 **loss（困惑度）**：
- loss 持续下降说明模型在学习
- 最终 loss 越低，模型语言能力越强
- 可以用模型生成一些文本，主观评估流畅度

更严格的评估需要在下游任务（如文本分类、问答等）上测试，但那是微调阶段的事了。

### Q7：预训练和微调的代码有什么区别？

| 区别点 | 预训练 | 微调 |
|--------|--------|------|
| 模型初始化 | `from_config()`（随机初始化） | `from_pretrained()`（加载已有权重） |
| 数据格式 | 纯文本 | 问答对 / 指令格式 |
| 数据量 | 海量（GB~TB） | 较少（MB~GB） |
| 训练时间 | 很长（天~周） | 较短（小时~天） |
| 学习率 | 较大（1e-4 ~ 1e-5） | 较小（1e-5 ~ 1e-6） |
